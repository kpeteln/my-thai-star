## 2. Sequence Diagrams

### 2.1 Booking Creation Flow

Complete flow from Angular UI through REST service, Business Facade, Repository, to Email notification.
Shows both **common booking** (single party) and **invited booking** (with guests) paths.

```mermaid
sequenceDiagram
    autonumber
    actor Customer as Customer
    participant UI as Angular BookTableComponent
    participant BTS as BookTableService
    participant REST as BookingmanagementRestServiceImpl
    participant Logic as BookingmanagementImpl
    participant BRepo as BookingRepository
    participant IGRepo as InvitedGuestRepository
    participant Mail as MailService
    participant DB as Database

    Customer->>UI: Fill booking form (date, name, email, guests)
    activate UI

    UI->>BTS: postBooking(bookInfo)
    activate BTS
    BTS->>REST: POST /bookingmanagement/v1/booking (BookingCto)
    activate REST

    REST->>Logic: saveBooking(bookingCto)
    activate Logic

    Logic->>Logic: requireNonNull(booking)
    Logic->>Logic: mapList(invitedGuests to InvitedGuestEntity)

    loop For each invited guest
        Logic->>Logic: buildToken(email, GB_) guestToken via MD5
        Logic->>Logic: invite.setAccepted(false)
    end

    Logic->>Logic: buildToken(email, CB_) bookingToken via MD5
    Logic->>Logic: setCreationDate(now)
    Logic->>Logic: setExpirationDate(bookingDate minus 1h)

    Logic->>BRepo: save(bookingEntity)
    activate BRepo
    BRepo->>DB: INSERT INTO Booking
    DB-->>BRepo: BookingEntity with generated id
    deactivate BRepo

    loop For each InvitedGuest
        Logic->>IGRepo: save(invitedGuestEntity)
        activate IGRepo
        IGRepo->>DB: INSERT INTO InvitedGuest
        DB-->>IGRepo: InvitedGuestEntity
        deactivate IGRepo
    end

    Logic->>Mail: sendConfirmationEmails(resultEntity)
    activate Mail

    alt Booking type = COMMON (no guests)
        Mail-->>Customer: Booking Confirmation Email with CB_ token
    else Booking type = INVITED (with guests)
        Mail-->>Customer: Host Confirmation Email
        loop For each invited guest
            Mail-->>Customer: Guest Invitation Email with GB_ token link
        end
    end
    deactivate Mail

    Logic-->>REST: BookingEto (id, bookingToken)
    deactivate Logic

    REST-->>BTS: 200 OK BookingEto
    deactivate REST

    BTS-->>UI: BookingResponse
    deactivate BTS

    UI-->>Customer: Booking confirmed with token displayed
    deactivate UI

    Note over Customer,DB: Guest clicks GB_ link in email to accept or decline invite
    Customer->>REST: GET /invitedguest/accept/{guestToken}
    REST->>Logic: updateInvitedGuest(token, accepted=true)
    Logic->>IGRepo: save(updated entity)
    IGRepo->>DB: UPDATE InvitedGuest SET accepted=true
```
